# Upstream proposal: complete observable label coverage

Prepared 2026-10-03 for `edugraph-content` / `edugraph-dataset`. This is an implementation proposal and evidence package, not an upstream change or corrected release.

The required outcome is **all legitimate, independently observable ontology facts about the atomic task**, across Areas, Scopes and Abilities. A true applicable label must not be omitted because it is common, less discriminative, absent from a curriculum target, or missing from the generator's current schema. Optional removal of logically redundant labels is a separate, versioned serialization decision; it must preserve recoverable meaning and cannot remove independent facts.

This objective supersedes a reading of earlier classifier audit recommendations that would select only salient or distinguishing labels. Eligibility and evidence still matter: a label naming a cognitive performance or independently learned mathematical concept must satisfy that definition, rather than being inferred merely from decorative text or an incidental symbol. The task is not to add every ontology neighbor or every prerequisite.

## Evidence and version boundaries

The image evidence comes from dataset **v0.30.0-03**, Hugging Face artifact commit `9b509867e898490615be3f59bc2f31fac429389c`, consumed with ontology 0.30.0 by the completed classifier baseline. All 1,968 released rows were counted; selected original images were visually inspected. The 250 final predictions now support exploratory diagnosis, not a fresh blind assessment.

The inspected dataset source is release commit `d1920909e34bfe368cc22a4aea6e591690db796d` and current immutable HEAD `374055902a5105d39408ba43e72c3dbea56ce7e5`. Of 23 selected files compared byte-for-byte, 21 are unchanged, including label assembly, VQA policy, arithmetic digit schemas, decimal-conversion declarations and the explanation-view declarations cited below. The measurement-data spec and generator have added fraction subdivisions, but retain optional single-frame labeling. **There is no verified build receipt joining the GitHub release source to the Hugging Face artifact commit.** Source claims describe those snapshots; visual claims describe the actual released images.

The baseline used ontology **0.30.0**; the current dataset package instead pins **`0.30.0-pre.8.275616e7115c`**, corresponding to ontology source `275616e7115c61c4d2080baf0e16ddf71a961163`. That preview includes renamed and additional concepts, such as `GroupedExpression` replacing `ParenthesesUsage`, `ArithmeticLaws`, role-specific number types and decimal-precision facets. An implementation against HEAD must generate an exhaustive eligible-label inventory from that exact preview and reconcile its definitions and relations. The baseline facet examples below do not establish complete coverage of the preview catalog.

Local supporting evidence is in `reports/numeric-scope-hypothesis-20261003/artifact-coverage.json`, `reports/label-convention-audit-20261003/`, and `reports/upstream-label-completeness-20261003/source-manifest.json`. Source snapshots and SHA-256 values are retained locally. No upstream files, gold labels or paid services were changed.

## Why currently passing labels can still be incomplete

The current system is a good constraint satisfier, but its output set is bounded by declarations. `resolvePlannedConfigurations` unions generator/view invariants and selected schema labels; only afterward does `generatePlannedDraw` sample mathematical data. An undeclared digit, fraction subtype or ability therefore cannot appear just because the rendered instance demonstrates it. This is unchanged between [release assembly](https://github.com/christian-bick/edugraph-dataset/blob/d1920909e34bfe368cc22a4aea6e591690db796d/src/lib/planned-generation.ts#L60-L93) and [current assembly](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/lib/planned-generation.ts#L60-L93).

That design is explicit in [IMPL-G3](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/docs/implementation-generator.md#L36-L45): ordinary changes of operand values remain instance variation. For complete observable annotations, such variation can nevertheless change digit count, numerical bounds, divisibility, or other true instance facts. Configured capabilities and realized facts need distinct identities; adding more target permutations alone cannot close this gap.

VQA currently answers a different question: whether the **supplied** labels are supported. Its prompt includes supplied label definitions, and the response validator requires exactly that label list. An omitted label cannot be returned as an additional label check under the existing response contract. Ambiguous supplied labels also pass. See [prompt construction](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/lib/vqa-evaluator.ts#L129-L165), [exact response-list validation](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/lib/vqa-policy.ts#L88-L105), and [global checklist](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/visuals/views/checklist.md#L15-L20). Another pass with the same contract does not test completeness.

## Concrete coverage gaps and extension points

| Surface | Verified mechanism / artifact evidence | Required extension under complete coverage |
|---|---|---|
| Generic arithmetic | `arithmetic-ops-pairs` always declares integers, base 10, two operands and single step; its schema controls sign, zero, range and some arithmetic properties, but has no operand-digit capability. Released `6+2=8`, `28×3=84` and `443+353=796` omit applicable digit labels. [Spec](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/arithmetic/arithmetic-ops-pairs/spec.ts#L16-L51). | Add common realized operand-fact assessment across arithmetic producers. A missing schema becomes an implementation gap, not a reason to classify the facet as inapplicable. Preserve requested digit constraints separately when generation also needs to be controlled by them. |
| Place-value arithmetic | Its schema supports only selected digit predicates, while other profiles can realize additional digit facts. `44+2` emits one-/two-digit facts; the same facts are omitted in generic multiplication. [Spec and predicates](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/place-value/place-value-arithmetic/spec.ts#L18-L78). | Reuse the arithmetic fact assessment for every realized profile, including subtraction and degenerate values. Define source operands separately from decomposition intermediates. Do not infer all digit facts from a small set of requested flags. |
| Partial-products multiplication | Its schema explicitly declares complete paired digit profiles, including single×single; `6×1` and `8×3` therefore have both single-digit labels. It has no numeric-range or step-complexity declaration. [Profiles and invariants](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/arithmetic/multi-digit-multiplication/spec.ts#L13-L54). | Keep the positive digit behavior and evaluate other applicable facets independently. Step count must follow the actual requested/worked procedure, not merely the name of the multiplication strategy. |
| Decimal/fraction conversion | The producer samples numerator 1–9 over 10 or 1–99 over 100, so every generated fraction is proper. Conversion views declare only broad `FractionNumbers`. Actual `98/100` and `7/10` artifacts confirm the missing proper-fraction fact. [Sampling](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/fraction/decimal-notation/generator.ts#L10-L29), [view declarations](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/visuals/views/numbers/numbers-fraction-to-decimal/spec.ts#L6-L16). | Emit `ProperFractions` for the supported concrete values; independently assess unit/nonunit, denominator, equality, scale and reference-frame facts. If proper becomes generator-owned invariant, remove overlapping broad view ownership according to SPEC-8 rather than duplicate ownership. Optional broad-ancestor serialization remains separate. |
| Reference frames in measurement | `useSingleFrame` is optional and restricted to fractional selections; it changes subdivision sampling. Yet the payload carries one unit and one observation series even when false. A fraction numberline declares a single frame invariantly, while a single-unit line plot can omit it. [Measurement spec](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/statistics/measurement-data/spec.ts#L25-L55), [payload](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/statistics/measurement-data/generator.ts#L21-L36), [numberline invariant](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/visuals/views/numbers/numbers-fraction-line/spec.ts#L6-L11). | Separate subdivision configuration from the fact that one reference frame is used. Assess the actual frame identities exposed by the projection, for integers as well as fractions. Count multiple diagrams sharing a frame correctly; do not equate diagram count with frame count. |
| Written explanation abilities | The properties-explanation view declares only `ProcedureUnderstanding`; pattern and place-value explanation views also declare `TextualArticulation`. The inspected associativity artifact explicitly requests and displays written explanation, so this is a coverage candidate under the user's complete-facts objective. [Properties](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/visuals/views/operations/operations-properties-explanation/spec.ts#L6-L12), [patterns](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/visuals/views/operations/operations-pattern-explanation/spec.ts#L6-L17), [place value](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/visuals/views/place-value/place-value-arithmetic-explanation/spec.ts#L5-L11). | Review every view for the complete independently evidenced ability conjunction. Do not limit output to the leaf's distinguishing ability. Preserve requested action in questions and demonstrated action in solutions; a finished object alone does not prove how it was produced. |
| Operation and strategy Areas | The audited whole-tens self-subtractions were initially ambiguous visually, but source explicitly excludes the partitioning strategy because those views lack decomposition and partial differences. [Source rule](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/generators/place-value/place-value-arithmetic/spec.ts#L31-L36). | Completeness is not permission to add the strategy from the layout. Conversely, when an operation and a strategy are both independently evidenced, assess both. `expands`/`integrates` do not automatically add or suppress either claim. |

The coverage count is descriptive: digit facets occur on 64/1,968 released rows, operand cardinality on 736, step complexity on 596, zero on 648, sign on 946, base on 930 and ranges on 826. These are **not annotation completeness percentages**: the denominator includes tasks to which particular facets do not apply. The images establish concrete omissions; a complete applicability audit is still needed to estimate their prevalence. A single-digit example with labels and a three-digit example without them also rule out a simple numerical-complexity explanation. Curriculum grades were not inferred from filenames.

## Proposed architecture

Keep generation label-driven. Add an orchestration-owned annotation stage, rather than having pure `generator.ts` implementations emit ontology labels or having renderers inspect raw labels. Explicitly amend the architecture and stable rules where necessary before implementation.

1. **Requested claims:** preserve the original curriculum target and desired constraints, with their existing matching semantics.
2. **Selected capabilities:** preserve the admitted generator/view labels, configuration and replay receipt. These explain why the requested task could be generated.
3. **Realized facts and evidence:** evaluate the mathematical payload together with the prepared view projection and mode. Numeric predicates use typed mathematical witnesses; view predicates use explicit actions, units, frames, representations and visible solution evidence. Record label, rule version, evidence path and producer/view ownership.
4. **Observable fact set:** retain every applicable, true, independently supported eligible label. Record `not_applicable`, `false`, and `unresolved` separately in the audit; an unimplemented detector or missing capability is **unresolved**, never `not_applicable`. Unresolved applicable facets block a completeness claim or are explicitly quarantined for adjudication.
5. **Serialization and derived view:** optionally remove only redundant facts under an accepted, versioned policy, retaining a derivation proof and recoverable closure. Keep all independent facts. Neither `partOf` nor progression relations authorize label deletion/addition. A label-count target or preference for distinguishing labels is not a valid filter.

Changing only `problem.labels` would be unsafe. The existing target-coverage assertion uses specialization capability coverage, so a canonical numerical fact connected by `implies` cannot silently replace a configured bound there. Preserve planned claims and annotation facts separately; add explicit fact-to-target proof where supported, without changing general matching to accept unrelated implication relationships. [Coverage assertion](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/lib/label-contracts.ts#L72-L80).

A practical implementation can begin with reusable typed assessments for arithmetic pairs/triples, fraction values and measurement frames, plus explicit view action witnesses. Use small domain adapters where payload shapes differ. Do not force new digit configuration into every generator merely to describe an already generated value; config controls generation, while the new assessment records realized facts. Keep an inventory linking **every eligible ontology label** to an assessment, an explicit unsupported task domain, or an unresolved coverage ticket. Candidate routing may reduce work, but must be tested for recall and allow missing-candidate discoveries.

## Facet review inventory

| Dimension | Required review inventory | Evidence boundary |
|---|---|---|
| Scope: numerical | Number kind; sign; zero; base/notation; bounds; divisibility/parity; operand count; operand/dividend/divisor digit counts; step complexity and interval magnitude | Define applicability and value domain for each facet. Source operands, outputs, intermediate values, scale ticks and frame capacity are not interchangeable. Do not reuse one list of numbers for all predicates. |
| Scope: representation and context | Units/scales; physical/visual representations; arrangement; equal shares; fraction subtype/common numerator/denominator; reference-frame count; expression/statement structure | A shared physical unit and several diagrams can still form one frame. A diagram or caption must actually witness the property. |
| Area | Operations, equations/inequalities, quantity/concept relationships, laws, strategies, notation competence and independently required domain knowledge | Seeing a symbol is not automatically an independently learned notation task. Assess every true Area, not only the generator's principal Area. Do not derive prerequisite operations from progression relations. |
| Ability | Execution, inversion, understanding, interpretation, inference, concept derivation/classification, formalization, visual/spatial performance, reading and articulation | Preserve all independently elicited/performed actions. Explicitly distinguish understanding the content from merely having text on the page; retain action evidence in solution mode. The rule applies uniformly across views and grades. |

This inventory is a starting organization of the baseline catalog, not a manually maintained whitelist or a complete preview inventory. Generate the implementation inventory from the exact pinned ontology, including all current preview additions when targeting dataset HEAD. Newly added ontology labels or definitions must reopen relevant coverage reviews, including labels absent from existing gold.

## QA and acceptance gates

**Deterministic checks first.** Add unit/property tests for each fact assessment, boundary and applicability decision, then integration tests over real generator/view combinations and both modes. Required examples include:

- `6+2`, `6×1` and `8×3`: both single-digit operand facts independent of the selected layout or target; `44+2`/`28×3`: one-/two-digit facts; `443+353`: both three-digit facts. Result digit count must not replace operand digit count.
- Boundary and degenerate cases: zero, negatives, repeated operands, an unknown input, one-operation versus displayed multistep work, improper/unit fractions, mixed numbers, and a bound exactly on its threshold. Resolve known ontology consistency blockers before enforcing blanket rejection from relation helpers.
- Proper decimal fractions `98/100` and `7/10` receive the proper subtype independently of whether the target requested it. Test changing a fraction across a subtype boundary without losing unrelated labels.
- One frame versus genuinely multiple frames, in integer/fractional plots and conversions; distinguish several representations of one quantity from several reference frames.
- Explicit written explanations retain understanding and written articulation where both definitions are fulfilled. Questions and solutions do not silently inherit an action that the solution no longer demonstrates.
- Both positive and negative evidence for operation/strategy pairs, including whole-tens self-subtraction, nontrivial partitioning without regrouping, and regrouping. No rule may equate “no borrowing” with “no partitioning.”

**Completeness-specific visual QA.** Retain supplied-label support checking, then add a separate result for missing independently supported labels/facets. The new schema must permit missing-label findings; its candidate inventory must not be limited to current gold or module declarations. Review candidate positives against definitions and pixels, and blind at least a sampled second annotation pass to the proposed gold. Uncertain support/completeness must remain visible as unresolved rather than silently producing a completeness pass. This work does not require live VQA for every numeric predicate; use deterministic witnesses for exact arithmetic facts and reserve visual review for observability and semantic actions.

**Identity and publication.** Include annotation rules, applicability/candidate inventory, ontology definitions and evidence policy in dependency/cache identity—even when a newly relevant label is absent from current gold. Current VQA identity only hashes image, supplied-label context, checklists and policy; reuse would otherwise miss omitted-label changes. [Cache construction](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/lib/vqa-cache.ts#L145-L169). Version the new response contract, recompute affected annotations and invalidate affected VQA records explicitly. Keep public `file_name`/`labels`/`solution` stable unless a deliberate schema version is published; store richer fact/provenance receipts in operational sidecars. [Public projection](https://github.com/christian-bick/edugraph-dataset/blob/374055902a5105d39408ba43e72c3dbea56ce7e5/src/lib/dataset-merge.ts#L53-L72).

Release acceptance requires a before/after label diff with reasons; no unresolved applicable coverage tickets for the claimed supported domain; deterministic reruns; validated evidence for additions and removals; complete preservation of independently valid old facts; and explicit review of new contradictions rather than treating all recorded partial-conflict relations as automatic impossibility. Publish a new dataset version and annotation policy. Preserve the original classifier baseline and separately evaluate the new release; the old model scores do not measure the new full-label objective.
